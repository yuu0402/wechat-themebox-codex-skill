# Visual QA And Troubleshooting

Use this reference when reviewing a ThemeBox package, diagnosing ugly imports, or fixing visual defects after device testing.

## Top Navigation And Bar Issues

Top navigation defects are common because bars combine backgrounds, text colors, safe-area behavior, and dark-mode resources.

Check these resources and settings first:

- `topbar_bg.png`
- `topbar_bg_Dark.png`
- `chat_topbar_bg.png`
- `chat_topbar_bg_Dark.png`
- `tabbar_bg.png`
- `tabbar_bg_Dark.png`
- tabbar icon normal and `HL` selected states
- `NAVBAR_LOAD_METHOD` and `CHATNAV_LOAD_METHOD` when analyzing advanced ThemeBox config exports
- WeUI colors for top bars, navigation text, separators, material backgrounds, and glyph colors
- Topbar assets are functional UI surfaces, not illustrations. Use a flat or very subtle texture/gradient, no character faces, no busy pattern, no large focal object, and no high-contrast detail under title/back/menu icons. Preserve measured height and safe-area padding exactly.

Common symptoms and fixes:

- Top bar turns solid black or white: missing dark/light bar resource or mismatched color token.
- Title text is unreadable: adjust navigation text colors and contrast against `topbar_bg`.
- Chat page top bar differs from other pages: check `chat_topbar_bg` separately from `topbar_bg`.
- Bar has a visible seam or wrong height: match the original exported dimensions and avoid cropping safe-area padding.
- Tabbar icons float too high or too low: check `tabbar_size`, `tabbar_top_enabled`, `tabbar_top`, and whether the icon has uneven transparent padding.
- Selected tab icon looks wrong: ensure `HL` variants are real hand-drawn selected states, not recolored leftovers.
- Dark mode shows light icons or light backgrounds: provide `_Dark` variants and verify light/dark token pairs.
- Before approval, test navigation title, back arrow, menu glyphs, and separators against `topbar_bg` and `chat_topbar_bg` in light and dark mode. Aim for at least 4.5:1 contrast for text where practical, and reject any background that makes nav glyphs ambiguous at phone size.

## Script-Generated Placeholder Rejection

Do not ship ugly script-drawn placeholder icons in a hand-drawn theme.

Allowed script work:

- building zips
- copying and renaming approved assets
- resizing/canvas-normalizing approved hand-drawn assets
- validating dimensions and alpha
- generating color XML/JSON from tokens
- creating inventory reports/contact sheets

Not allowed for final assets:

- primitive script-drawn circles, squares, arrows, emojis, or generic pictograms
- recolored default system icons
- autogenerated placeholder badges used as finished art
- low-effort canvas fills, flat letters, or text labels in place of drawn icons
- assets that do not include the requested original character language when the theme requires a character-led full pack

If a script creates temporary placeholders, mark them as `placeholder` in the inventory and replace them before release.

## Cropping And Independent Icon Checks

Every icon must be an independent complete icon on a transparent canvas.

Reject assets when:

- the subject is cropped off at the edge
- only a partial slice of the character is visible without functional meaning
- the icon is a screenshot crop from a larger illustration
- the icon relies on a background scene to be understandable
- the canvas has a white, black, colored, or rounded rectangle backing that is not part of the actual target slot
- transparent margins are uneven enough to make the icon appear off-center in WeChat
- the icon clips after ThemeBox scaling

Fixes:

- redraw the full object or character-integrated symbol
- add transparent padding without changing the target slot size
- center the visual mass, not only the bounding box
- review at small size and against light/dark WeChat backgrounds

## Launch, Wallpaper, And Background Requirements

For original-character themes, `launch.png`, wallpapers, covers, and page backgrounds should be designed from the same original character bible, not left as plain color fills unless the user explicitly asks for minimalism.

Recommended coverage:

- `cover.png`: theme preview with the character and theme mood.
- `icon.png`: package/app-style theme icon based on the character identity.
- `launch.png`: startup/splash artwork based on the character, with enough quiet space for WeChat launch behavior.
- `default_bg.png`, `main_bg.png`, `contacts_bg.png`, `discover_bg.png`, `me_bg.png`, `chat_bg.png`, `album_bg.png`: page backgrounds with subtle character motifs, patterns, or scene elements.
- Give each page background a restrained role: `main_bg` = broad theme mood, `contacts_bg` = quiet list-safe texture, `discover_bg` = slightly more playful motif, `me_bg` = strongest personal/character cue, `album_bg` = media-safe neutral surface, `chat_bg` = lowest contrast.

Rules:

- Backgrounds may be opaque or softly textured because they are surface resources.
- Do not make backgrounds visually busy behind text and chat content.
- Keep chat backgrounds lower contrast than covers or launch art.
- Keep dark-mode backgrounds separately designed; do not blindly invert light backgrounds.

## Review Workflow

Before release:

1. Build a contact sheet for all icons.
2. Review contact sheet at full size and small preview size.
3. Verify all icon assets have alpha and no matte background.
4. Verify all expected payment/service assets are in the inventory.
5. Open key screens on device or simulator: chat, home/session, contacts, discover, me, pay/service, search, file preview, settings.
6. Record every defect as filename plus symptom plus fix.
